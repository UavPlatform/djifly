# 飞手端（DJI Fly）产品设计计划稿

> 版本：v1.0 | 日期：2026-06-21 | 状态：计划阶段

## 一、产品定位与现状分析

### 1.1 产品定位

飞手端是面向**无人机飞手（Rider/Pilot）**的专业级移动应用，核心价值是：

> **让飞手在一个 App 内完成「接单 → 沟通 → 飞行作业 → 交付结算」的完整业务闭环，同时保留专业级飞行控制能力。**

与用户端（飞翼通 Flutter App）形成双边市场：
- **用户端**：发布任务、支付、验收
- **飞手端**：接单、执行、交付

### 1.2 现状差距分析

当前 `djifly/` 的定位是一个**纯飞行工具**，只有两个页面：

| 维度 | 现状 | 目标 | 差距 |
|------|------|------|------|
| 用户系统 | ❌ 无登录/注册 | 完整的飞手账号体系 | 完全缺失 |
| 首页 | ❌ 无（直接进入飞行状态检测） | 数据总览 + 快捷入口 | 完全缺失 |
| 任务接单 | ❌ 无 | 任务大厅 + 筛选 + 接单 | 完全缺失 |
| 任务管理 | ❌ 无 | 进行中/已完成任务管理 | 完全缺失 |
| 消息沟通 | ❌ 无 | 与用户实时聊天 | 完全缺失 |
| 个人中心 | ❌ 无 | 个人信息 + 收益 + 设置 | 完全缺失 |
| 无人机管理 | ❌ 无（仅自动注册） | 绑定/解绑/状态查看 | 完全缺失 |
| 飞行控制 | ✅ 已有 FlightScreen | 保留并增强 | 需接入任务上下文 |
| 平台通信 | ✅ 已有 WebSocket | 保留并扩展 | 需增加聊天 WS |

### 1.3 后端 API 就绪度

后端已具备飞手端所需的**全部核心 API**：

| 模块 | API 状态 | 说明 |
|------|----------|------|
| 飞手注册/登录 | ✅ 就绪 | `/rider/register`, `/user/login`, `/user/refresh` |
| 任务大厅 | ✅ 就绪 | `/rider/square` (获取空闲任务) |
| 接单/取消/完成 | ✅ 就绪 | `/rider/accept`, `/rider/cancel`, `/rider/complete` |
| 我的任务 | ✅ 就绪 | `/rider/my-tasks`, `/rider/my-tasks/history` |
| 聊天会话 | ✅ 就绪 | `/chat/session/*`, `/chat/Message/*` |
| 无人机绑定 | ✅ 就绪 | `/rider/drone/bind`, `/rider/drone/list`, `/rider/drone/unbind` |
| 飞行遥测 | ✅ 就绪 | WebSocket `/ws/drone` UAV_STATUS 事件 |
| 直播推流 | ✅ 就绪 | TRTC START_LIVE 命令处理 |
| 支付/结算 | ⚠️ 部分就绪 | 后端有支付模块，但无飞手端收益/提现 API |

**结论：飞手端的功能开发无需等待后端新增 API，可以直接对接现有接口。**

### 2.1 飞手核心业务闭环


### 2.2 关键业务场景

**场景一：新飞手入驻**
1. 下载 App → 注册页填写账号密码 + 可选填 DJI 设备 ID
2. 注册成功自动登录 → 引导绑定无人机
3. 进入首页，查看任务大厅

**场景二：日常接单作业**
1. 打开 App → 首页看到今日数据 + 新任务提醒
2. 进入任务大厅 → 筛选感兴趣的任务类型
3. 查看任务详情（描述、航点、赏金）→ 确认接单
4. 联系用户沟通需求细节
5. 连接无人机 → 进入飞行控制台执行任务
6. 完成任务 → 等待用户验收
7. 用户确认 → 任务完成，收益到账

**场景三：任务执行中的沟通**
1. 作业过程中用户发来消息
2. 飞手在飞行控制台收到消息通知浮层
3. 降落后回复消息，协商调整

**场景四：查看历史与收益**
1. 进入个人中心 → 查看历史接单记录
2. 查看累计收益、评分、完成率
3. 筛选/搜索历史任务

## 四、各页面详细设计

### P01 SplashPage — 启动页

**职责**：App 冷启动展示 + 自动登录判断 + DJI SDK 初始化

**页面结构**：
```
┌──────────────────────────┐
│                          │
│                          │
│                          │
│         [LOGO]           │
│        飞手端             │
│       DJI Fly            │
│                          │
│      ┌──────────┐        │
│      │ 加载中... │        │
│      └──────────┘        │
│                          │
│                          │
│                          │
└──────────────────────────┘
```

**业务逻辑**：
1. 显示品牌 Logo 和 App 名称
2. 并行执行：
   - DJI SDK 初始化（复用现有 `DjiSdkManager`）
   - 检查本地是否有有效 Token
3. 初始化完成后：
   - 有 Token → 跳转首页（HomeScreen）
   - 无 Token → 跳转登录页（LoginPage）
4. 超时处理：SDK 初始化超过 5 秒仍跳转（SDK 状态在 StarterScreen 再检查）

**设计要点**：
- 启动页停留时间不超过 2 秒（即使 SDK 已初始化完成）
- 使用 `AnimatedVisibility` 做品牌渐入动画
- 背景色与 App 主色调一致（深色系，延续飞行控制台的视觉风格）

**业务逻辑**：

- 登录中状态：按钮显示 loading，禁止重复点击
- 服务器设置默认折叠，点击展开（参考 Flutter app 的 LoginPage 设计）

- DJI ID 字段有说明文案，降低填写门槛
- 表单校验实时反馈（输入时即校验，而非提交后）

```kotlin
class AuthInterceptor @Inject constructor(
    private val tokenStore: TokenStore
) : Interceptor {
    override fun intercept(chain: Interceptor.Chain): Response {
        val token = tokenStore.getAccessToken()
        val request = if (token != null) {
            chain.request().newBuilder()
                .addHeader("Authorization", "Bearer $token")
                .build()
        } else {
            chain.request()
        }
        return chain.proceed(request)
    }
}
```

```kotlin
class ChatWebSocketClient @Inject constructor(
    private val okHttpClient: OkHttpClient,
    private val gson: Gson
) {
    private val _messages = MutableSharedFlow<ChatEnvelope>(extraBufferCapacity = 64)
    val messages: SharedFlow<ChatEnvelope> = _messages

    fun connect(userId: Long, baseUrl: String) {
        val wsUrl = "${baseUrl.replace("http", "ws")}/ws/$userId"
        val request = Request.Builder().url(wsUrl).build()
        okHttpClient.newWebSocket(request, object : WebSocketListener() {
            override fun onMessage(webSocket: WebSocket, text: String) {
                val envelope = gson.fromJson(text, ChatEnvelope::class.java)
                _messages.tryEmit(envelope)
            }
            // ... reconnection logic
        })
    }
}
```

### 7.2 关键里程碑

| 里程碑 | 验收标准 |
|--------|----------|
| M1: 可登录 | 飞手可注册、登录、Token 自动续期 |
| M2: 可接单 | 飞手可浏览任务大厅、查看详情、确认接单 |
| M3: 可执行 | 飞手可从任务详情进入飞行控制台、完成任务 |
| M4: 可沟通 | 飞手可与用户实时聊天 |
| M5: 可管理 | 飞手可管理无人机、查看个人数据 |
| M6: 完整闭环 | 端到端流程走通：注册→接单→飞行→完成→沟通 |

### 7.3 风险与依赖

| 风险 | 影响 | 应对 |
|------|------|------|
| DJI SDK 与 Navigation Compose 兼容性 | StarterScreen/FlightScreen 需要 FragmentActivity | 使用 `AndroidView` 包装 DJI Widget，避免 Fragment 依赖冲突 |
| 聊天 WebSocket 与无人机 WebSocket 并发 | 两个长连接可能互相影响 | 独立 OkHttpClient 实例，独立重连策略 |
| 后端缺少飞手统计 API | 首页数据总览无法展示真实数据 | Phase 1 先从任务历史本地计算，Phase 2 后端补充 |
| Token 安全存储 | DataStore 明文存储不安全 | 引入 EncryptedSharedPreferences 或 androidx.security-crypto |
| 横竖屏切换 | 飞行控制台需要横屏，其他页面竖屏 | 使用 `Activity.requestedOrientation` 动态切换 |
